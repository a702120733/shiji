# 云端界面与本机数据

拾集可以把无个人数据的网页代码放到 Vercel，让浏览器直接连接同一台电脑上的拾集服务。Vercel 不代理资料请求，也不保存用户的账号资料、书签、图片或视频。采集、分类、导入、搜索、分组与媒体读取都由本机服务完成。

## 部署与连接

1. 将开源仓库连接到 Vercel，项目的 **Root Directory** 设为 `cloud`，作为静态站点部署。不要把 `data/`、本机生成的 `liked/index.html`、`saved/index.html` 或其他个人资料上传到仓库或构建产物。部署完成后取得正式的 `https://…vercel.app` 域名。
   修改导入页或 Chrome 页面后，先运行 `python3 scripts/build_cloud_ui.py` 同步无数据的界面文件，再提交 `cloud/ui/`。
2. 在使用者自己的电脑安装并启动拾集；将**精确的正式域名**告诉本机服务（不含末尾斜杠）：

   ```bash
   SHIJI_CLOUD_ORIGIN=https://你的域名.vercel.app ./run.sh
   ```

   服务继续只监听 `127.0.0.1:8879`，数据目录仍为 `~/Library/Application Support/Shiji/data/`。如果改用登录后自动启动服务，应在安装登录项时传入相同的 `SHIJI_CLOUD_ORIGIN`。
3. 在同一台电脑的 Chrome 中打开部署域名，点击连接本机服务；浏览器可能要求允许该站点访问本地网络。随后在本机弹出的配对页确认站点域名并授权。成功后即可在公开网址内使用自己的本机资料库。

该模式依赖本机服务持续运行。同一个公开网址在另一台没有安装拾集、没有配对或没有该用户数据的电脑上，只会显示连接入口，不会显示这台电脑的资料。它不提供跨设备同步。部署域名变更后须重新配置本机 `SHIJI_CLOUD_ORIGIN` 并配对；预览域名不会自动获得授权。

## 安全边界

- 公网只托管界面文件。浏览器直接请求 `127.0.0.1`，请求和媒体不经过 Vercel API、云端代理或数据库；本机服务不得绑定 `0.0.0.0` 或开放公网端口。
- 本机服务只接受配置的精确线上来源，并要求用户在本机确认配对。不要把配对令牌写进 URL、Git、日志或网页构建产物。
- 配对后的线上 JavaScript **能够读取浏览器展示的本机资料**。因此必须信任该域名的发布者和更新流程；如果托管账号或站点脚本被篡改，本机存储本身并不能防止资料被网页读取或上传。不要在页面接入不受信任的第三方脚本。
- Chrome 对公开 HTTPS 站点访问本机地址可能显示 Local Network Access 授权提示。用户需主动允许；其他浏览器及旧版本可能需要回到 `http://127.0.0.1:8879/import` 使用本地版。[Chrome 官方说明](https://developer.chrome.com/docs/modern-web-guidance/guides/security/local-network-access)
- 开启 Codex 自动分类时，选中的正文和媒体证据仍会发送给用户自己的模型服务进行分析；“本机存储”不改变这项原有行为。
